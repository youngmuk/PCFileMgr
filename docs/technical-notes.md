# PCFileMgr

Windows용 로컬 디스크 용량 분석·조건별 파일 정리 유틸리티입니다. C# / .NET 10 / WPF로 구현했습니다.

## 실행

- `artifacts\PCFileMgr\PCFileMgr.exe`를 실행하거나 루트의 `Run.cmd`를 더블클릭합니다.
- 제공된 EXE는 **Windows x64용 자체 포함 배포본**입니다. 별도 .NET 설치가 필요 없습니다.
- 특정 폴더를 바로 분석하려면 `PCFileMgr.exe "D:\대상 폴더"`처럼 경로를 전달합니다.
- 관리자 권한을 요청하지 않습니다. 현재 계정이 읽을 수 있는 파일을 집계합니다.

## 사용 순서

1. 왼쪽의 C:, D: 등 로컬 드라이브를 누르거나 `폴더 선택`으로 분석 대상을 고릅니다. 주소 입력 후 Enter 또는 `분석 / 변경 확인`도 가능합니다.
2. 분석이 끝나면 파일·폴더 크기에 비례한 사각형 지도가 나타납니다. 폴더의 면적은 모든 하위 파일 크기의 합계입니다.
3. 폴더 사각형이나 목록을 더블클릭하거나 왼쪽 트리에서 폴더를 선택하면 해당 폴더의 바로 아래 항목별 용량을 표시합니다. 파일 사각형을 클릭하면 목록의 파일이 선택됩니다.
4. 오른쪽에 확장자, 최소/최대 크기, 이름 일부를 입력하고 `조건에 맞는 파일 찾기`를 누릅니다. 모든 조건은 AND로 결합됩니다.
5. `정리 후보`에서 처리할 파일을 직접 선택합니다. 자동으로 전체 선택하지 않습니다.
6. `선택 파일 검토…`에서 전체 경로·개수·용량을 확인하고 확인란을 체크한 다음 `휴지통으로 보내기`를 누릅니다.
7. 완료 후 실제로 처리한 파일이 포함된 폴더와 상위 합계를 갱신합니다. 실패·건너뛴 파일은 결과 창에 표시합니다.

## 분석 캐시와 변경분 갱신

- 완료된 분석을 **Windows 문서 폴더의 `PCFileMgr\Cache`**에 자동 저장합니다. Windows가 알려주는 실제 문서 경로를 사용하므로 문서를 다른 드라이브나 OneDrive로 옮긴 경우에도 해당 경로를 따릅니다. 실행 파일 위치나 작업 폴더와는 무관하며 같은 Windows 사용자 계정에서 공유합니다. 경로·크기·수정/생성 시각·속성과 폴더 합계를 저장하며 파일 내용은 저장하지 않습니다.
- 이전 `%LOCALAPPDATA%\PCFileMgr\Cache`는 새 위치에 해당 분석 캐시가 없을 때만 읽습니다. 변경 기록까지 복원하고 검증한 뒤 새 위치에 완전한 캐시를 저장합니다. 이전 파일은 삭제하지 않으며, 시작할 때 모든 캐시를 복사하지 않습니다. 문서 폴더가 클라우드 동기화 대상이면 캐시에도 그 동기화 설정이 적용됩니다.
- 앱 실행 중에는 Windows 변경 알림을 사용합니다. **변경이 없는 재요청은 폴더 내용을 다시 열거하지 않습니다.** 변경이 있으면 해당 폴더의 바로 아래 항목을 확인하고 상위 합계만 갱신합니다. 새 폴더는 그 내부까지 분석합니다.
- 변경 없는 하위 트리는 공유합니다. 변경 때마다 수백만 개 항목을 복사하지 않습니다. 디스크 캐시에도 변경된 폴더만 작은 추가 기록으로 저장하며, 32회 누적 후 전체 스냅샷으로 합칩니다.
- 재시작 대조 후 변경이 없으면 기존 캐시를 다시 직렬화·압축하지 않습니다. 실행 중 변경 없는 재확인에서는 같은 화면의 트리와 지도를 다시 만들지 않습니다. 캐시 저장 위치 변경 후 첫 가져오기에는 새 위치에 저장하는 작업이 필요합니다.
- 최근 분석 범위 최대 8개는 드라이브를 전환해도 변경 감시를 유지합니다. 큰 파일 트리는 현재 범위만 메모리에 두며, 돌아오면 저장된 캐시와 누적 변경 기록을 사용합니다.
- 용량 지도 화면을 보고 있을 때 변경 사항을 자동 반영합니다. 잦은 갱신을 막기 위해 갱신 완료 후 최소 10초 간격을 두고 변경 알림이 잠잠해진 뒤 실행합니다. 정리 후보 선택·확인 창을 보고 있을 때는 자동 갱신을 미룹니다. `F5`로 즉시 확인할 수 있습니다.
- **앱을 다시 시작하면 마지막 분석의 캐시를 먼저 표시하고, 실행되지 않은 동안의 변경 여부를 전체 파일 메타데이터 목록과 대조합니다.** 폴더 시각만으로는 내부 파일의 변경을 판별할 수 없어 필요한 단계입니다. 파일 수가 많으면 이 확인에도 시간이 걸립니다. 확인 중에는 파일 정리를 잠급니다. 관리자 권한이나 시스템 서비스 설치는 필요 없습니다.
- 크기·수정 시각·생성 시각·속성을 함께 비교하므로 과거 시각으로 복사한 파일, 삭제, 이름 변경도 반영합니다. 분석 시각보다 최신인 파일만 찾는 방식이 아닙니다.
- 폴더 경로 아래에 마지막 **분석 시각 / 확인 시각 / 변경 감시 상태**를 표시합니다. 하단에는 실제 확인한 폴더 수와 재사용한 폴더 수가 표시됩니다.
- Windows 변경 알림이 넘치거나 감시가 실패하면 전체 메타데이터 대조 후 감시를 복구합니다. 캐시가 손상되거나 버전이 다르면 새로 분석합니다. 취소 시 이전 캐시를 보존합니다. 접근 권한 때문에 제외된 경로는 권한 변경 알림, 재실행 검증 또는 전체 재분석 시 다시 확인합니다.
- `전체 재분석` 또는 `Shift+F5`는 캐시를 무시합니다. 기존 버전에서 분석한 결과는 저장되어 있지 않으므로 **업데이트 후 최초 한 번은 분석이 필요합니다.**

### 조건 입력 예

| 목적 | 확장자 | 최소 | 최대 | 단위 |
|---|---|---|---|---|
| 1 GB 이상 동영상 | `.mp4, .mkv, .mov` | `1` | 비움 | GB |
| 100 MB 이상 압축 파일 | `zip, 7z, rar` | `100` | 비움 | MB |
| 10 MB 이하 로그 | `.log` | 비움 | `10` | MB |
| 0바이트 파일 | 비움 | `0` | `0` | B |
| 확장자 없는 파일 | `<없음>` | 비움 | 비움 | MB |

확장자는 대소문자를 구별하지 않으며 쉼표·공백·세미콜론으로 구분합니다. `*.zip`도 허용합니다. 마지막 확장자 기준이므로 `archive.tar.gz`는 `.gz`로 찾습니다. 비어 있는 크기 조건은 제한 없음입니다. 최소·최대 경계를 포함하며 `1 KB = 1,024 B`입니다. 조건을 바꾸면 이전 후보 선택이 초기화됩니다.

### 단축키

- `Ctrl+L`: 경로 입력
- `Enter`: 입력 경로 분석 / 선택한 폴더 열기
- `Alt+↑`: 분석 범위 내 상위 폴더
- `F5`: 최초 분석 범위의 변경분을 확인하고 현재 폴더로 복귀
- `Shift+F5`: 캐시를 무시하고 전체 재분석
- `Esc`: 진행 중인 분석·검색·파일 처리 중지 요청

## 집계와 파일 처리 기준

- 집계값은 **파일의 논리적 크기**입니다. 압축·희소 파일의 실제 디스크 점유량, 하드 링크 중복, NTFS 메타데이터 때문에 드라이브 사용량과 다를 수 있습니다. 하드 링크는 경로마다 집계합니다.
- 숨김·시스템 파일도 읽기 권한이 있으면 집계합니다. 파일의 내용은 읽지 않으며 네트워크로 전송하지 않습니다.
- 접근 거부, 삭제·이동 중인 항목, 연결 지점·심볼릭 링크, `$Recycle.Bin`, `System Volume Information`은 제외하고 부분 집계를 표시합니다. 일부 클라우드 파일도 연결 속성 때문에 제외될 수 있습니다. 하단 `제외 항목`에서 최대 500개의 사유를 확인합니다.
- 네트워크·UNC 경로는 지원하지 않습니다. 로컬 고정/이동식 드라이브를 대상으로 합니다.
- 0바이트 항목은 면적이 없으므로 목록에서 확인합니다. 양수 크기 항목이 400개를 넘으면 상위 398개와 나머지의 합계로 그래프를 그립니다. 나머지는 일반 항목과 임시 항목으로 나누어 최대 2개로 묶으며, 아래 목록에는 모든 항목이 표시됩니다.
- 정리는 **파일만** 대상으로 합니다. 폴더 전체를 재귀 삭제하지 않습니다. 시스템·읽기 전용·연결 파일은 정리 후보에서 제외합니다.
- 삭제 직전에 선택 범위, 경로의 연결 속성, 파일 크기·수정/생성 시각을 다시 확인합니다. 분석 후 변경된 파일은 처리하지 않습니다. 파일을 편집 중인 프로그램을 닫고 정리하는 것이 좋습니다.
- Windows `IFileOperation`의 휴지통 기능을 사용하며, 영구 삭제 작업은 콜백에서 거부합니다. 휴지통을 지원하지 않는 드라이브/파일이나 이동 실패는 오류로 남깁니다. 영구 삭제로 자동 전환하지 않습니다.
- **휴지통으로 이동한 파일은 휴지통을 비우기 전까지 디스크 공간을 차지합니다.** 복원은 Windows 휴지통에서 할 수 있습니다. 앱에서 휴지통을 비우지는 않습니다.
- 분석 중 취소한 미완료 결과는 파일 정리에 사용하지 않습니다. 파일 처리 취소는 현재 Windows 작업이 끝난 후 다음 파일부터 적용됩니다.
- 분석은 메모리에 파일 메타데이터를 보관합니다. 파일 수가 매우 많은 드라이브는 메모리와 최초 분석 시간이 더 필요합니다. 최신 변경분을 즉시 확인하려면 F5를 누릅니다.

## 화면 표시와 아이콘

- 왼쪽 드라이브·폴더 패널과 본문 사이의 경계를 좌우로 드래그해 너비를 조절합니다. 경계를 선택한 뒤 방향키로도 조절할 수 있습니다. 왼쪽 패널과 본문의 최소 너비를 유지하며, 창 크기가 바뀌면 두 영역이 함께 조절됩니다.
- 세로·가로 스크롤바는 어두운 화면에 맞춘 둥근 형태입니다. 전체 폭/높이 10px, 보이는 손잡이 두께 6px이며, 마우스를 올리거나 끌면 민트색으로 표시합니다. 마우스 휠·손잡이 드래그·빈 영역 클릭으로 이동할 수 있습니다.
- 임시 파일·폴더는 지도, 폴더 트리, 파일 목록과 정리 후보에서 주황색으로 구분합니다. 지도와 유형 열에는 `임시`라는 글자도 표시합니다.
- `Temp`, `Tmp`, `Cache`, `.cache`, `__pycache__` 등 알려진 임시/캐시 폴더와 그 내부, `.tmp`, `.temp`, `.part`, `.crdownload`, `.swp` 등 임시 확장자, `~$`로 시작하거나 `~`로 끝나는 임시 파일명을 사용해 판별합니다. 정확한 목록은 `PCFileMgr.Core/TemporaryClassifier.cs`에 있습니다. 색상은 이름에 따른 분류이며, 자동 삭제나 자동 선택을 뜻하지 않습니다. 일반 `.bak` 파일은 임시로 분류하지 않습니다.
- 앱 아이콘은 민트색 폴더와 용량 지도 모양이며 EXE, 창 제목 표시줄/작업 표시줄, 화면 머리글에 등록했습니다. `PCFileMgr/Assets/AppIcon.ico`는 16~256px 크기를 포함합니다. 이미지 생성 기록은 `PCFileMgr/Assets/IconSource.md`, 변환 스크립트는 `Build-Icon.ps1`입니다.

## 개발·빌드

### 성능 개선 조사 (2026-10-25)

현재 재시작 시 전체 파일 메타데이터 대조가 필요하며, 압축 캐시도 전체 메모리 트리로 복원합니다. 저장 위치 변경만으로 이 비용이 없어지지는 않습니다.

| 기법 | 이 앱에 대한 적용 판단 | 상태 |
|---|---|---|
| USN 변경 저널 | NTFS가 앱 종료 중 기록한 변경을 마지막 USN부터 읽어 재시작 시 전체 대조를 줄이는 최우선 후보. 볼륨 ID·저널 ID·USN 및 파일/부모 ID 매핑이 필요하며, 저널 기록 유실·권한 부족·미지원 드라이브에서는 전체 대조로 복귀해야 함 | 조사 완료, 미구현 |
| SQLite 인덱스와 폴더별 지연 로딩 | 루트 합계와 바로 아래 항목만 먼저 읽고, 탐색/검색 시 필요한 데이터를 조회. 수백만 항목의 전체 압축 해제·객체 생성·메모리 사용을 줄이는 설계 후보 | 조사 완료, 미구현 |
| ReadyToRun | 사전 컴파일로 시작 시 JIT 작업 감소 가능. 파일 크기가 증가하고 작은 앱은 효과가 작을 수 있어 비교 측정 후 적용 판단. 파일 재탐색 시간은 줄이지 않음 | 조사 완료, 미적용 |
| 불필요한 작업 생략 | 변경 없는 재시작 검증 후 캐시 재압축 생략, 실행 중 변경 없는 재확인의 트리·지도 재구성 생략 | 이번 업데이트 적용 |

일반적인 볼륨 USN API는 관리자 권한이 필요하므로 권한 있는 보조 프로세스/서비스도 검토해야 합니다. 화면 가상화와 데이터 지연 로딩은 별개입니다. 효과 측정은 창 표시, 캐시 표시, 변경 대조 완료 시간을 분리하고 메모리/디스크 IO를 비교해야 합니다. 아직 대용량 드라이브의 개선율을 측정하지 않았습니다.

공식 자료: [Windows 변경 저널](https://learn.microsoft.com/en-us/windows/win32/fileio/change-journals), [저널 식별자·권한](https://learn.microsoft.com/en-us/windows/win32/fileio/using-the-change-journal-identifier), [저널 읽기 API](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_read_usn_journal), [SQLite 인덱스](https://www.sqlite.org/queryplanner.html), [WPF UI/데이터 가상화](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-controls), [ReadyToRun](https://learn.microsoft.com/en-us/dotnet/core/deploying/ready-to-run).

### 빌드 방법

.NET 10 SDK 및 Windows가 필요합니다. 일반 빌드/테스트에는 외부 NuGet 라이브러리를 사용하지 않습니다. 자체 포함 배포 시 Microsoft의 공식 런타임 팩을 받기 위해 NuGet 연결이 필요할 수 있습니다.

```powershell
# 자체 포함 EXE: artifacts\PCFileMgr\PCFileMgr.exe
.\Build.ps1

# .NET 10 Desktop Runtime 설치 PC용 작은 배포본
.\Build.ps1 -FrameworkDependent

# 핵심 기능·안전장치 검증 (사용자 파일을 삭제하지 않음)
.\Test.ps1

# 위 검증 + 테스트가 직접 만든 임시 파일 1개의 실제 휴지통 이동
.\Test.ps1 -RecycleSmoke
```

- `PCFileMgr.Core`: 탐색·집계, 조건 필터, 경로 검증, 파일 처리 조정, 면적 그래프 계산
- `PCFileMgr`: WPF 화면, 지도 렌더링, Windows 휴지통 연동
- `PCFileMgr.Tests`: 추가 테스트 프레임워크 없이 실행 가능한 검증 프로그램

Windows Shell 연동 참고: [IFileOperation::SetOperationFlags](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags), [IFileOperationProgressSink::PreDeleteItem](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-predeleteitem).
